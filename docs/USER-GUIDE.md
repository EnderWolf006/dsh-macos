## 1. 它是什么

以"桌面应用"的方式使用 DeepSeek Harness（dsh）：双击打开，官方 Web 对话界面出现在原生窗口里，后端服务器自动拉起与管理。它**不改变 DSH 的任何能力**，只提供原生外壳。

## 2. 环境要求

| 项 | 要求 |
|---|---|
| macOS | 13 或更高 |
| Node.js | 已安装（终端 `node -v` 有输出） |
| 网络 | 能访问 npm 与镜像源（更新后端时） |

## 3. 安装

```bash
curl -fsSL https://raw.githubusercontent.com/EnderWolf006/dsh-macos/main/install.sh | bash
```

或从 Releases 下载 `DSH.MacOS.Desktop.zip`，把 `DSH Desktop.app` 拖入应用程序文件夹。

> 若浏览器下载版双击报"已损坏"：这是 macOS 对网络下载文件的隔离机制，执行 `xattr -cr "/Applications/DSH Desktop.app"` 即可；推荐改用上方一键命令，无此问题。

## 4. 首次启动

1. 打开应用，先看到服务器状态面板
2. 应用自动拉起 dsh 后端（首次约数秒）
3. 如弹出通知权限请求，建议允许（会话导出提醒会用）
4. 就绪后窗口切换为官方对话界面

## 5. 界面与菜单

菜单名「服务器」：启动/停止服务器 · 刷新页面 · 显示主窗口 · 在浏览器中打开 · 前往开放平台 · 发送测试通知。

要点：

- 关闭窗口 ≠ 退出（Dock 常驻），Cmd+Q 才是真正退出
- 连接中断时页面顶部出现横幅并自动重试，内容不丢；恢复即消失
- 折叠侧栏、拖拽带双击最大化等桌面行为与系统一致
- 编辑菜单支持 `Ctrl+F` 查找，`Command +` / `Command -` / `Command 0` 控制全局缩放

## 6. 设置（Cmd+,)

| 设置 | 默认 | 说明 |
|---|---|---|
| 端口 | 3080（只读） | 后端固定端口 |
| 启动命令 | `dsh --profile web` | 改完即时生效 |
| 自动启动服务器 | 开 | 打开应用即拉起 |
| 退出保持服务器 | 关 | 默认退出带走后端 |
| 开机自启 | 关 | 需在 /Applications |
| 语言 | 跟随当前 DSH 设置 | 中文 / English 双向同步 |
| 回合完成通知 | 仅在失焦时 | 可改为从不或始终 |
| 权限 / 提问通知 | 开 | 可分别关闭 |

状态区可查看服务器状态、桥接信息（pid / 版本 / 运行时长）；关于区可检查 DSH 更新与应用更新。

## 7. 通知与会话导出

- 通知基于系统 UserNotifications，可在系统设置自由管理
- 导出会话自动保存到 `~/Downloads/session-log-<ID>.zip` 并通知 + Finder 定位

## 8. 更新

- **后端**：设置 → 关于 → 检查 DSH 更新。先查后问：确认后才下载（镜像加速 + 进度），校验通过自动清理旧缓存并重启新后端；失败不动旧版
- **应用**：重跑一键安装命令，或设置 → 检查应用更新获取提示

## 9. 退出与卸载

- 退出：Cmd+Q（默认联动停止自启后端）
- 卸载：删 `/Applications/DSH Desktop.app`；（若装了）删 `~/Library/Application Support/DSH Launcher.app`；`killall Dock`

## 10. 排障速查

| 现象 | 处理 |
|---|---|
| 找不到 dsh | 装 Node.js；启动命令保持默认 |
| 一直"启动中…" | 数秒等待；查 `lsof -iTCP:3080` |
| 白屏 | 菜单"服务器"→刷新页面 |
| 没通知 | 检查系统设置→通知授权 |
| 升级后权限异常 | 见 README 免责声明旁的 tccutil 说明 |
